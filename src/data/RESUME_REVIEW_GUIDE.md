## 📋 데이터 구조 요약

`resume.json`은 아래 구조입니다. 첨삭 시 **필드 구조(키)는 그대로 유지**하고 값(텍스트)만 다듬어 주세요.

| 키 | 설명 |
|----|------|
| `basics` | 이름·직무·이메일·GitHub·포트폴리오·위치·전화 |
| `about` | 소개 문단. 강조 부분은 `**볼드**` 마크다운으로 표기됨 |
| `skills[]` | `{ category, skills[] }` — 프론트/백/도구/언어 |
| `experience[]` | `{ company, position, period, summary?, groups[{label?, items[]}], tech? }` — 최신순 |
| `projects[]` | `{ title, subtitle?, role?, mainTasks[{title, details[]}], tech[], link? }` |
| `education` | `{ degrees[], courses[], certifications[] }` |

## ✂️ 첨삭 요청 프롬프트 (복사해서 사용)

> 아래는 백엔드/풀스택 웹 개발자의 이력서 데이터(JSON)입니다.
> **채용 담당자·기술 면접관 관점**에서 첨삭해 주세요.
>
> **첨삭 기준**
> 1. **성과 중심**: "무엇을 했다"가 아니라 "어떤 문제를 어떤 방법으로 해결해 어떤 결과를 냈다"로. 정량 수치(%, 시간, TPS 등)를 살리고, 없는 항목은 수치화 여지가 있는지 지적.
> 2. **동사·표현**: 모호한 표현("담당", "참여", "지원")을 능동적·구체적 동사로. 중복 표현 제거.
> 3. **일관성**: 문체(음슴체/합쇼체), 기술 표기(예: `Chart.js`, `Vanilla JS`, `Spring WebFlux`)를 전체적으로 통일.
> 4. **직무 적합성**: 백엔드/풀스택 포지션 관점에서 강조할 항목과 덜어낼 항목 제안.
> 5. **분량**: 너무 긴 불릿은 압축, 임팩트 약한 항목은 병합/삭제 제안.
>
> **출력 형식**
> - (A) **수정 제안 요약**: 섹션별로 핵심 피드백을 불릿으로.
> - (B) **첨삭된 전체 JSON**: 입력과 **동일한 키 구조**를 유지한 채 값만 수정한 완성본. (구조를 바꾸지 말 것)
> - (C) **추가로 확인이 필요한 부분**: 수치·사실관계 등 작성자에게 되물어야 할 항목 목록.
>
> **주의**
> - `basics`의 연락처·URL 등 사실 정보는 임의로 바꾸지 말 것.
> - 없는 성과·수치를 지어내지 말 것. 개선 여지가 있으면 (C)에 질문으로 남길 것.
> - `about`의 `**볼드**` 표기 규칙은 유지(강조 위치는 조정 가능).
>
> [여기에 resume.json 내용 붙여넣기]
